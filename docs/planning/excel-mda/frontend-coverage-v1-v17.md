## Gaps closed in this pass

- V3/V4 previously required a batch created outside the web UI. **Nuevo lote** now accepts the extractor's complete `.json` envelope, validates its published limits and source identity, explicitly previews against the database and separately saves the administrative batch. The route does not accept binary `.xlsx`; there is no browser Excel parser or partial-source workaround. The body limit is 16 MiB, including the save wrapper. Read and save results are bound to the reviewed source/preview.
- An unconfirmed V4 outcome retains the exact workbook and previewId for explicit recovery. Known stale/conflict outcomes require a new preview. The first creator and creation time belong to the returned batch; a deduplicated batch can belong to another JEFE and have a later administrative version. Loading, local parse errors, network errors, stale results and confirmed receipts have separate states; errors remain visible inside the shared modal and toast.
- V10's editor previously represented one period. It now preserves independent drafts and cross-page evidence choices for up to 25 periods. Adding never copies recipient/date/state facts. Removal requires confirmation; every edit invalidates the complete result. The result selector and paginated warnings/blockers belong to the selected period. The V11 confirmation shows the entire set and sends one intent, with one UUID/body for uncertain recovery. No partial client-side application.
- V11 receipts with `mda-closed-assignment-plan-1` are read under their archived shape, without inventing V12 evidenceVersion/amendment fields or a version zero. Mixed/malformed receipts fail visibly. Compatibility does not enable writes, correction of old plans or replay. See `apps/web/src/features/imports/legacy-closed-application.md` for serializer evidence and remaining storage limitations.
- Assignment and timeline reads now display the original/effective values and correction metadata already returned by the current backend. Group and legacy import provenance remain distinct. The timeline compares the actual delivery or return endpoint, without fabricating a second endpoint or assigning the importer as the historic executor. These are read integrations; later correction-write workflows remain separate.

## Verification levels and limits

Pure/model, transport, asynchronous-hook and rendered-component tests cover strict envelopes, all 1–25 period sizes, duplicated endpoints, selected-period pagination, immutable recovery and detached callbacks. Browser verification uses the existing Dialog/Field/Select/DataTable owners, desktop and narrow mobile layouts, light/dark/system and reduced-motion settings. These checks do not certify every browser, assistive technology or 200% zoom combination.

An isolated real PostgreSQL 18/API environment with synthetic Juan Pérez QA data verified V3/V4 preview, batch creation/read/dedup and V9 capture followed by a real V10/V11 two-period plan/application/read. A blocked set produced no partial assignment/receipt; identical recovery produced no duplicate, and an altered body with the same key was rejected. Asset/current stock/movements stayed unchanged by closed-history application. This is integration evidence for those paths, not a production rollout, original-workbook validation, late-transaction fault injection or a real 25-period application. Archived rules1 receipts use contract-shaped fixtures; no genuine historical production receipt was obtained.

The complete frontend suite, TypeScript, scoped lint, enabled/default builds, independent review and browser results are recorded with the implementation handoff in [frontend.md](frontend.md). Earlier dated reports in that file remain historical evidence; they do not describe the current creation/compatibility gaps.

## Work remaining beyond contract coverage

- Feature flags remain false by default. Enabling requires the deployed API/schema and an explicitly authorized operational pilot.
- Drafts and uncertain intents remain in memory. Close/discard and browser unload warn, but internal Back, session changes and reload do not provide durable recovery. Do not store private workbook/evidence bodies in browser storage as an implicit fix.
- Single-candidate V7 editing and explicit page-sized V9 capture are deliberate bounded workflows; the backend accepting a larger array does not require automatic bulk selection. Tintas/undated-retirement policy is not decided by the UI.
- V18 current-group consultation and V19 explicit group/evidence decisions are implemented in [frontend.md](frontend.md#continuación-frontend-decisiones-y-pertenencia-v19--2026-10-26). Later planning/application/document workflows begin at V20. Showing already-returned effective assignment provenance is not implementation of all later backend workflows.
- Cryptographic authenticity, production Excel correctness, large-file performance under representative devices, migration/deployment readiness and production concurrency remain separate verification tasks. Client guards do not recompute server fingerprints or business rules.
